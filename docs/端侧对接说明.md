# 鸿蒙客户端对接改动清单

本项目只提供服务与说明，不包含或改写鸿蒙代码。具体文件名随开源客户端版本不同，按以下职责定位改动。

- **BASE_URL**：将网络层地址改为网关地址，例如开发机局域网 IP 的 `http://192.168.1.10:8080`。真机 localhost 指向手机自身。确认设备可访问服务端口，并按客户端平台规则配置开发 HTTP 网络权限。
- **登录**：登录请求改为 POST /auth/login，JSON 为 username/password。先判断 body.status==200，再取 data.token、data.nickname。后续除登录外统一添加 Authorization: Bearer token。
- **统一响应解析**：普通接口返回 HTTP 200 不表示业务成功；读取 status/message/data。400 展示 message；404 按资源不可用处理；500 提示重试。
- **401 处理**：读取 body.status==401 后清除本地 token、取消当前聊天、跳转登录，不只拦截 HTTP 401。
- **会话接口**：创建取数字 data 作为 conversationId；列表取 data 数组。历史消息请求 page/size，data 直接是按 id 升序的消息数组。删除成功移除本地会话及历史。
- **模型选择**：演示默认 modelCode=mock。gpt/glm/deepseek 需要服务端启用并配置密钥；未启用会返回业务 400。
- **POST SSE**：使用支持请求体与 Authorization 的流式 HTTP 客户端；浏览器风格只支持 GET 的 EventSource 不能直接调用。请求体包含 conversationId/modelCode/content。
- **响应分流**：先检查 Content-Type。application/json 时解析 Result（包括 401）；text/event-stream 时进入增量读取。不要等待整个 HTTP body 收齐再显示。
- **增量解析**：UTF-8 解码器必须跨网络块保留未完整字节；保留半行缓冲，以空行分隔 SSE 事件，将 data: 后内容作为 JSON 解析。TCP 块可能拆开中文或跨多个事件，不能假设一块就是一条事件。支持 LF/CRLF，忽略注释行。每条 JSON 是 StreamEvent，不存在 Result 包装。
- **事件状态**：delta 将 content 追加到当前 assistant；done 才标记完成并刷新历史；error 展示 content 并标记失败。连接关闭但无 done 视为中断。取消/离开页面时关闭客户端连接，让服务端取消上游调用。不要自动重发 POST，避免重复保存 user。

联调顺序：登录 → 创建 mock 会话 → POST SSE 观察 20 个 delta + done → 刷新消息历史 → 删除会话。再验证错误密码、过期 token、无 token、无效页码与不存在会话。
